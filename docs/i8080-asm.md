# Intel 8080: instructions and programs as OCaml values

`rivet.i8080_asm` (`targets/i8080/i8080_asm.ml`) builds i8080 instructions and
whole programs without text, as `rivet.riscv_asm` and the other `*_asm` libraries
do for their targets. Its closure is the encoder, the image library and the
direct pipeline stages: no lexer, parser or text front end.

```ocaml
let open I8080_asm in
Program.assemble ~origin:0x100
  [ insn (lxi sp 0xf000);
    insn (mvi b 3);
    label "loop";
    insn (dcr b);
    insn (jnz_e (symbol "loop"));
    insn (hlt ()) ]
(* Ok { origin = 0x100; bytes; symbols = [ ("loop", 0x105) ] } *)
```

## Builders

One per mnemonic and operand shape, named by the mnemonic (`in` is `in_`), each
selecting its `I8080_ops` entry: no opcode byte is listed in the library, and a
mnemonic missing from the table fails when the builder runs. An immediate or an
address is an `int` (`mvi a 42`); the `_e` variant takes an `Asm_core.Expr.t`
(`jnz_e (symbol "loop")`, `lxi_e hl (plus (symbol "table") (const 2))`). A
constant expression is folded, so its range is checked like a number's.
Instructions without operands take `()`.

| Operand | Type | Values | Instructions |
| --- | --- | --- | --- |
| byte register | `reg` | `b c d e h l m a` | `mov mvi inr dcr` and the ALU group |
| register pair | `` [ `Bc \| `De \| `Hl \| `Sp ] `` | `bc de hl sp` | `lxi inx dcx dad` |
| stack pair | `` [ `Bc \| `De \| `Hl \| `Psw ] `` | `bc de hl psw` | `push pop` |
| indirect pair | `` [ `Bc \| `De ] `` | `bc de` | `ldax stax` |

The pair classes are closed variants, so `mov bc a`, `push sp`, `ldax hl` and
`lxi psw 0` do not compile (`test/asm/neg`). What types cannot say is a
diagnostic of assembly: `mov m m` (the slot of `hlt`), the range of an immediate,
`rst 8`. The same checks guard the generic `I8080_encode.Instruction.Insn`, so a
hand-built instruction with the wrong operand count or class is a diagnostic from
lowering, not an exception.

## Programs

`I8080_asm.Items` repeats every builder, returning an item instead of an instruction, so a program is a plain
list with no `insn` in it:

```ocaml
let open I8080_asm.Items in
Program.assemble [ lxi sp 0xf000; mvi b 3; label "loop"; dcr b; jnz_e (symbol "loop"); hlt () ]
```

(`Program` is `I8080_asm.Program`; the operands, expression helpers and data items are the same values.)
The `insn` form stays for instruction values built elsewhere.

`insn`, `label`, `db`/`dw` (and `db_e`/`dw_e`), `ascii` and `space` build items.
`Program.assemble ?origin items` lowers them, plans and binds one section at
`origin` (default 0) through `Driver_direct.Pipeline_direct`, and returns the
origin, the bytes and every label's address. Duplicate and undefined labels,
operand shapes, ranges, and an origin or image outside the 64 KiB address space
are diagnostics. `Program.bind` is the final step the text path
(`I8080_text`) shares.

## Checks

`test/i8080/test_builders.ml`: every shape of `I8080_corpus` (614 instructions)
assembles to the bytes of its printed text, the corpus has a builder for every
table entry, labels resolve at several origins, and a recursive program runs to
`HLT` in the model leaving its result in RAM. The oracle leg assembles the
printed corpus with `asl` (`i8080-oracle-dis.sh … builders`, see
`docs/i8080-oracle.md`).
