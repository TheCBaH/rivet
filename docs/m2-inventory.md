# Milestone 2 fixture inventory

Measured from `asm/fixtures/compcert-3.17/*/`, generated by
`tools/asm-fixture-gen.sh --regen` and `tools/asm-fixture-oracle.sh all` with
CompCert 3.17 and GNU binutils 2.44. This file is the authority the M2 plan
defers to: its form lists were provisional until this existed, and anything
below that contradicts a plan bullet wins.

Regenerate with `make asm-oracle`, then re-derive this file. A change here is a
change to M2's scope, not a refresh.

## 1. Cases

Every entry is `int asm_test_entry(void)` returning **42**, so the ABI helpers —
which install no arguments — give a determined result (plan X1).

| case | shape | second global |
|---|---|---|
| `args_arith` | `volatile` locals, add/sub/mul | `asm_test_sum`, exported and never called, for argument lowering without a call |
| `cond_select` | two comparisons and a select | — |
| `loop` | counted loop, backward branch | — |
| `direct_call` | `asm_test_callee(20) + 2` | `asm_test_callee` |
| `global_ldst` | read/modify/write a `.data` global | `asm_test_global` |
| `return42` | M1 baseline, unchanged | — |

Three cases have two globals, so `policy_for`'s single-global entry inference
(`pipeline.ml:308`) no longer determines an entry. That is plan M2.C's explicit
entry selection, and it is now a measured requirement rather than a prediction.

## 2. Instruction forms

M1's baseline is `return42`. Everything else is new work.

| target | M1 baseline | added by M2 |
|---|---|---|
| x86_32 | `addl leal movl ret subl` | `cmpl imull jg jge jl jmp call cmovne xorl` |
| x86_64 | `addq leaq movl movq ret subq` | `cmpl imull jg jge jl jmp call cmovne xorl leal subl` |
| arm | `add bx ldr mov str sub` | `b bge bgt bl blt cmp ite mla movt movw mul` + condition suffixes `moveq movne` |
| aarch64 | `add ldr mov movz ret stp` | `adrp b b.ge b.gt b.lt bl cmp csel madd orr str` |

Notes that change planned work:

- **`ite eq` (ARM) assembles to zero bytes.** GAS accepts the Thumb-2 If-Then
  mnemonic in A32 as an assertion; the following `moveq`/`movne` carry their own
  condition fields. It is a consume-and-discard pseudo-instruction, handled like
  `.cfi_*`, not an encoding.
- **`mla`/`madd` are genuine fused multiply-add forms**, one each, from
  `a + (b * c)`.
- **No magic-number division.** `args_arith` deliberately omits `/` and `%`;
  CompCert lowers them to signed multiply-high sequences (`smull`/`mla`,
  `madd`/`sxtw`, `imull`/`shrl`), which is a lowering axis of its own and is out
  of M2's scope.
- x86 `cmovne` appears in `cond_select` on both profiles — a conditional move,
  not only a branch.
- **x86-64 needs the `0x67` address-size prefix.** `args_arith` and
  `direct_call` contain `leal 0(%edi,%edi,1), %eax` and `leal 2(%eax), %eax`:
  32-bit registers used as *addresses* in 64-bit mode, which GNU encodes with a
  `67` prefix. Encoding them without it assembles cleanly and addresses the
  wrong registers, so this is a correctness gap rather than a byte difference.
  *Implemented*, derived from the operand exactly as REX is.

## 2a. Alignment padding: our nop table is not GAS's

The first fixture with two functions is the first with real `.align 16`
padding, and it disproves an assumption `x86_family.ml` had already flagged as
unverified ("the first fixture that pads is what turns the claim into
evidence").

GNU fills the ten bytes between `asm_test_callee` and `asm_test_entry` with a
single

```
66 2e 0f 1f 84 00 00 00 00 00    cs nopw 0x0(%rax,%rax,1)
```

Our table is the Intel-recommended one: it tops out at nine bytes and has no
`2e` (CS override) forms, so it would emit two nops where GNU emits one, with
different bytes. Two consequences, both real and both bounded:

1. **Byte parity.** Matching GNU on any padded fixture needs GAS's table, not
   Intel's. The two differ in the `66 2e` prefix run and in reaching ten and
   eleven bytes.
2. **Decoding.** The codec has no `nop` form at all, so
   `--dump-disasm=diagnostic` fails on any section containing padding with
   `no form matches these bytes`. That is why the `direct_call` fixture
   disassembles only up to its first pad today.

Neither blocks the encoding path — instructions are byte-correct either side of
the padding — but both block the `direct_call` and `args_arith` byte gates.

## 3. Directives

Measured union across all six cases. The plan listed `.byte .short .word .4byte
.quad .ascii .asciz .string .p2align .space .zero` speculatively; **none of them
occur**, so per the plan's "only if M2.A's inventory shows them" they are all
deferred.

| target | directives |
|---|---|
| x86_32 / x86_64 | `.align .data .globl .long .section .size .text .type` + `.cfi_adjust_cfa_offset .cfi_endproc .cfi_startproc` |
| arm | the above with `.balign` for `.align`, plus `.arch .arm .eabi_attribute .fpu .syntax` and `.cfi_rel_offset` |
| aarch64 | as x86 with `.balign`, plus `.cfi_rel_offset` |

Against M1, the additions are exactly:

- **`.long`** — the only data directive M2 needs.
- **`.type … , @object`** — M1 saw only `@function`. `Directive.sym_kind`
  already has `Object`.
- **`.data`** — the second allocatable section.
- **`.cfi_rel_offset`** — another `.cfi_*` to drop; already covered by
  `is_metadata` (`directives.ml:53`).

So M2.I's directive work is `.long` and `@object`. `.p2align`, `.space`/`.zero`,
`.comm`, `.bss` and NOBITS are all deferred, and the plan's `.p2align`
normalization is not needed in M2.

## 4. Sections

`.text` everywhere; `.data` only in `global_ldst`; `.rodata` never; no `.bss`,
no `.comm`, no NOBITS — the acceptance gate in `tools/asm-fixture-gen.sh`
enforces that. `.note.GNU-stack` is declared-not-allocated, as in M1.

So M2's multi-section requirement is exactly **two** allocatable sections in one
module, in one case.

## 5. Relocations

`objdump -r`, `.text` only. `.eh_frame` records from `.cfi_*` are excluded —
those directives are discarded at parse and never reproduced.

**Only `direct_call` and `global_ldst` carry any `.text` relocation.**
`args_arith`, `cond_select`, `loop` and `return42` carry none on any target:
GNU resolves their branches while assembling. Those branches are still fixups
for this assembler, which has to lay out, relax, bind and patch them — the
asymmetry plan O1 exists to classify.

| target | case | offset | rel/rela | type | symbol | addend |
|---|---|---|---|---|---|---|
| x86_32 | direct_call | `0x34` | rel | `R_386_PC32` | `asm_test_callee` | in field |
| x86_32 | global_ldst | `0x0b`, `0x13` | rel | `R_386_32` | `asm_test_global` | in field |
| x86_64 | direct_call | `0x33` | rela | `R_X86_64_PLT32` | `asm_test_callee` | `-0x4` |
| x86_64 | global_ldst | `0x0f`, `0x19` | rela | `R_X86_64_PC32` | `asm_test_global` | `-0x4` |
| arm | direct_call | `0x34` | rel | `R_ARM_CALL` | `asm_test_callee` | in field |
| arm | global_ldst | `0x10`, `0x14` | rel | `R_ARM_MOVW_ABS_NC`, `R_ARM_MOVT_ABS` | `asm_test_global` | in field |
| aarch64 | direct_call | `0x24` | rela | `R_AARCH64_CALL26` | `asm_test_callee` | `0x0` |
| aarch64 | global_ldst | `0x08`, `0x14` | rela | `R_AARCH64_ADR_PREL_PG_HI21` | `asm_test_global` | `0x0` |
| aarch64 | global_ldst | `0x0c`, `0x18` | rela | `R_AARCH64_LDST32_ABS_LO12_NC` | `asm_test_global` | `0x0` |

This is why O1's classifier is per target and per role rather than universal:

- a same-file **global** call keeps a record on all four targets, but x86-64
  spells it `PLT32` and x86-32 spells it `PC32` — treating those as
  interchangeable would discard the intent the gate tests;
- a **global data reference** is PC-relative on x86-64 and **absolute** on
  x86-32, so the plan's provisional `Pcrel32_data` is x86-64 only and x86-32
  needs `Abs32` for the same source construct;
- **branches to local labels** produce nothing anywhere.

The two RELA addends confirm the plan's derived PC-relative rule
`elf_addend = expr_addend + byte_offset − pc_bias`: `call` has `byte_offset = 1`
and `pc_bias = 5` (`1 − 5 = −4`), and `movl g(%rip)` has `byte_offset = 2` and
`pc_bias = 6` (`2 − 6 = −4`). Both match.

## 6. Expression positions

Where a symbol actually appears, which decides how far `Operand.t` has to
change (plan D2):

| target | construct | position |
|---|---|---|
| x86_32 | `movl asm_test_global, %eax` | bare absolute memory operand |
| x86_64 | `movl asm_test_global(%rip), %eax` | **memory displacement**, RIP-relative |
| arm | `movw r0, #:lower16:asm_test_global` | immediate with **modifier** |
| aarch64 | `adrp x16, asm_test_global` | bare operand |
| aarch64 | `ldr w0, [x16, #:lo12:asm_test_global]` | **memory offset with modifier, inside brackets** |
| all | `call`/`bl asm_test_callee` | branch target |

A top-level `Operand.Expr` variant is not sufficient: two of these are inside
memory operands and two carry modifiers, one of them inside brackets. That is
plan D2 and D3, confirmed by measurement.

## 7. Relaxation

GNU chose **short** branch encodings in every x86 case that has one:

| case | target | bytes |
|---|---|---|
| loop | x86_32 | `7d 08` (`jge`), `eb f0` (`jmp`) |
| loop | x86_64 | `7d 0a` (`jge`), `eb ee` (`jmp`) |

ARM and AArch64 are fixed-width and have no ladder. So the exact-byte gate
requires x86 `rel8` selection: always emitting the near forms would be correct
and would still fail. Plan M2.F0 is a measured requirement.

## 8. Controlled link

`oracle/linked/<section>.hex` holds bytes after `ld -T` at the addresses in
`tools/target-matrix.sh`, which mirror `abi.ml`: `.text` at `0x30000000`
(32-bit) / `0x40000000` (64-bit), `.data` at `+0x20000`. `oracle/linked/manifest.txt`
records section, address and file.

Unresolved bytes are not encodings — `direct_call/x86_64` holds
`e8 00 00 00 00` in the object and `e8 c9 ff ff ff` after linking — so the byte
gate compares post-link output for any case with relocations, and `text.hex`
stays comparable only for the four cases without.
